### 3. Wasabi Protocol
- **Date:** 2026-04-30
- **Loss:** $5,900,000
- **Chains:** Ethereum, **Base**, Berachain, Blast
- **Vector:** Single admin EOA key compromise — `wasabideployer.eth` held unchecked `ADMIN_ROLE` across all upgradeable vaults. No multisig, no timelock, no governance. UUPS upgrade proxy pushed malicious vault implementations across 4 chains simultaneously.
- **Attacker EOA:** `0x02228b0afcdbEdf8180D96Fc181Da3AF5DD1d1ab`
- **Funded via:** Tornado Cash
- **⚠️ Base chain directly affected** — vaults drained on Base in same block as Ethereum.

### 4. TrustedVolumes
- **Date:** 2026-05-07
- **Loss:** $5,870,000
- **Chain:** Ethereum (1inch Fusion ecosystem)
- **Vector:** Three chained bugs in custom RFQ swap proxy:
  1. `registerAllowedOrderSigner()` was permissionless — anyone could register as valid signer
  2. `fillOrder()` checked signer against attacker-controlled receiver, not the actual inventory holder
  3. `taker` field used as `from` address in token transfer — attacker set `taker = victim`
  - Replay protection broken: `saltStatus` wrote to one storage key, read from a different one
- **Setup cost:** 1 deployed contract + 4 wei USDC
- **Contract was never open-sourced. Team inactive for 1+ year.**

### 5. THORChain (3rd exploit)
- **Date:** 2026-05-15
- **Loss:** $10,700,000 (revised to $11M+ across 9 chains)
- **Chains:** Bitcoin, Ethereum, BSC, **Base**, Avalanche, Dogecoin, Litecoin, Bitcoin Cash, XRP
- **Vector:** Malicious node exploited GG20 TSS signing stack to leak vault key material. Private key reconstructed offline. A patch existed in GitLab 9 days before the exploit (`sign full ObservedTx wrapper to prevent proposer forgery`) but was never deployed.
- **Auto-halt:** THORChain's Mimir module halted the network for 12h42m — no human intervention required.
- **⚠️ Base chain directly affected** — assets drained on Base among 9 chains.
- **Context:** 3rd exploit in 5 years. $200M insolvency crisis. $1.2B in DPRK laundering through THORChain. Co-founder jpthor personally lost $1.2M to DPRK in Sep 2025.

### 6. Volo
- **Date:** 2026-05-21 (approx)
- **Loss:** $3,500,000 (net loss: ~$60K after recovery)
- **Chain:** Sui
- **Vector:** Admin private key compromised via social engineering. Three vaults hit (WBTC, XAUm, USDC). Volo self-disclosed and recovered nearly all funds.
- **Notable:** Only incident in this period with significant fund recovery.

### 7. New Market Trading (SquidRouterModule)
- **Date:** 2026-05-25
- **Loss:** $3,980,000
- **Chains:** Ethereum, **Base**, Arbitrum
- **Vector:** Third-party Gnosis Safe module accepted caller-supplied constant string as authentication proof. Anyone who read the source code could pass it. 88 Gnosis Safes drained in under 2 hours.
- **Attribution confusion:** Contract named "SquidRouterModule" on Basescan — Squid Protocol had no involvement. Built by New Market Trading, unaudited.
- **Attacker funded via:** 2.1 ETH from Tornado Cash
- **⚠️ Base chain directly affected** — Safes drained on Base.

### 8. Gravity Bridge
- **Date:** 2026-05-29
- **Loss:** $5,400,000
- **Chain:** Ethereum-Cosmos bridge
- **Vector:** Denom mapping poisoning. Attacker minted worthless tokens on Osmosis, embedded real Ethereum custody addresses in fabricated denom strings, called permissionless function that bridge accepted without validation. Fix was a lookup that already existed in codebase but was never called.
- **Attacker validator:** `julia666` with 80 GRAV self-delegation
- **Theft wallets:**
  - `0x7B582033061b96cC3F9421e73a749ED7C62da1F9`
  - `0x4d3ca32e687e871a58b78AcAc73bE59AC37C7A47`
- **Bridge status:** Offline at time of reporting. No postmortem issued.

### 9. DxSale

## Cross-Reference: ACP ERC-8183 Contracts & Base Chain

### Base Chain Exposure — CRITICAL

**Base chain appears in 3 of the 8 DeFi exploits tracked this period:**

| Incident | Base Affected | Vector on Base | Loss on Base |
|---|---|---|---|
| Wasabi Protocol | ✅ Yes | UUPS vault upgrade via compromised admin key | ~$1.9M (840.9 WETH) across vaults on Base |
| THORChain (3rd) | ✅ Yes | TSS key leak → cross-chain vault drain | Part of $11M multi-chain loss |
| New Market Trading | ✅ Yes | Gnosis Safe module with hardcoded auth string | Part of $3.98M multi-chain drain (88 Safes) |

**Pattern:** Base is being targeted as a secondary drain path in cross-chain exploits. Attackers consolidate on Ethereum/primary chains but execute simultaneous drains on Base where victims have deployed assets. The New Market Trading incident specifically deployed the malicious "SquidRouterModule" on Basescan, lending it false credibility via the verification badge.

### ERC-8183 Contract Assessment

**Note:** No public standard or registry exists for "ERC-8183" as of this sweep. This may refer to a private or pending EIP, or an internal contract identifier. **Recommendation:** If ERC-8183 contracts are deployed on Base, they share the threat surface documented above — particularly:
- **UUPS upgradeability risk** (Wasabi pattern): If any ERC-8183 implementation uses UUPS proxies with a single admin key, the same attack applies.
- **Gnosis Safe module risk** (NMT pattern): If ERC-8183 contracts are accessed via Safe modules, ensure the module's authentication is not based on caller-supplied constants.
- **Denom/mapping integrity** (Gravity Bridge pattern): If ERC-8183 contracts maintain token registries or cross-chain mappings, validate all inputs against an allowlist before writing.

### Systemic Risk: CRITICAL
- The dominant exploit patterns are **not novel**. Every major incident in this period was a variation of a known attack class:
  - Centralized admin keys (Wasabi, DxSale, TesseraDAO)
  - Missing authorization checks (TrustedVolumes, NMT)
  - Deferred patches (THORChain)
  - Trust-on-first-use registry poisoning (Gravity Bridge)
- The industry is experiencing the same attacks at increasing scale because the same architectural mistakes are being repeated.
