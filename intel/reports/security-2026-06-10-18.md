## ERC-8183 / ACP Contract Cross-Reference

### What is ERC-8183?
ERC-8183 is the **Agentic Commerce Standard** proposed by Virtuals Protocol and the Ethereum Foundation's dAI team (February/March 2026). It defines a trustless job lifecycle (Open → Funded → Submitted → Completed/Rejected) with programmable escrow, evaluator verification, and hook extensibility. It pairs with ERC-8004 for agent identity/reputation.

### Current Deployment Status
- **Ethereum mainnet:** Proposed standard, implementations in progress
- **BNB Chain:** Live implementation via BNBAgent SDK
- **Base:** Expected implementation (EVM-compatible); no confirmed production deployment yet
- **Arbitrum/Optimism:** Expected to follow

### Security Concerns for ERC-8183 / ACP Contracts

1. **Evaluator compromise risk:** The Evaluator is a single address (wallet, multisig, AI agent, or ZK contract) with unilateral power to approve/reject jobs. A compromised evaluator can drain all escrowed funds across active jobs.

2. **No on-chain delivery verification:** The standard relies on the evaluator's attestation. If the evaluator is an AI agent, prompt injection or model manipulation could lead to false approvals.

3. **Hook extensibility = attack surface:** Custom hooks for bidding, reputation, and privacy introduce unbounded smart contract complexity. Each hook is a potential entry point for reentrancy, access control bypass, or logic errors.

4. **Escrow lock-up risk:** Funds locked in escrow are only released on job completion/rejection. A stalled job (e.g., provider goes offline) creates capital inefficiency. The standard includes a `terminate` path, but termination conditions are hook-defined.

5. **$3M+ in prior unescrowed transactions:** Before ERC-8183, over $3M in agent-to-agent transactions occurred on Virtuals with no escrow, no delivery verification, and no recovery mechanism. This unescrowed transaction volume signals that the ecosystem has been operating in a high-risk mode.

6. **Base chain vulnerability landscape:** Trugard reported **34,000 vulnerabilities** across Base network contracts. The Arcadia Finance $3.5M exploit on Base (malicious `swapData` injection via `router.call()`) demonstrates the specific risk pattern: untrusted external contract calls bypassing access controls. This is directly relevant to ERC-8183 hook implementations on Base.

## VAPE Impact Assessment

### Direct Risk: 🟡 MODERATE
VAPE operates within the ACP ecosystem which uses ERC-8183/ERC-8004 primitives for agent commerce. The standard is still maturing, and the evaluator model introduces a centralization point that contradicts the trustless intent.

### Indirect Risk: 🔴 HIGH
The broader DeFi environment is deteriorating. Bridge exploits are systemic, social engineering campaigns are targeting protocol operators with months-long preparation, and DPRK-linked groups are actively infiltrating crypto organizations. Any VAPE-adjacent protocol (lending platforms, DEXs, bridges used for settlement) is at elevated risk.

### Key Recommendations
1. **Avoid new bridge exposure.** 14 of 14 major bridge exploits in 2026 were successful. Minimize cross-chain transaction volume. Prefer same-chain settlement.
2. **Audit all ERC-8183 hook implementations.** The hook extensibility model is the primary attack surface. Every custom hook should receive independent security review before deployment.
3. **Implement multi-evaluator quorum.** A single evaluator address with unilateral approval/rejection power is an unacceptable single point of failure. Require M-of-N evaluator consensus for jobs above a threshold value.
4. **Monitor Base chain deployments.** 34K+ vulnerabilities identified on Base. Any ERC-8183 deployment on Base should undergo rigorous third-party auditing, especially for external call patterns (the Arcadia Finance pattern).
5. **Social engineering hardening.** The Drift Protocol attack took 6+ months of preparation. VAPE operator security (key management, communications hygiene, access control) must be treated as a first-class security concern.
6. **Real-time on-chain monitoring.** The Resolv Labs exploit ($23M) demonstrated that off-chain infrastructure compromise can only be contained by on-chain detection. Deploy real-time anomaly detection for all VAPE-adjacent contracts.
7. **Upgrade control review.** The Wasabi Protocol exploit ($5.9M) exploited UUPS upgrade paths with no timelock. Ensure all upgradeable contracts have timelocks and multi-sig requirements.
