### Cross-Reference: ERC-8183 / ACP Contract Considerations
- No specific ERC-8183 standard exists in public EIP repositories. If referencing internal/custom contract standards:
  - **Admin key centralization** (Wasabi pattern) is the #1 threat to any upgradeable contract architecture (UUPS/proxy patterns with single admin).
  - **Bridge message integrity** — Any cross-chain messaging (LayerZero, Hyperlane, etc.) must validate message provenance; Kelp DAO exploit shows the cost of insufficient verification.
  - **Safe module trust assumptions** — New Market Trading exploit (third-party Safe module trusting caller-supplied data over msg.sender) is a direct analog risk for any contract relying on external modules.

### Risk Recommendations
1. **Mandatory multisig + timelock** for all admin/upgrade functions — no single EOA should hold unilateral control
2. **Bridge message verification** — Implement message provenance checks; do not trust cross-chain payloads without cryptographic verification
3. **Quarterly AI attack simulations** — As recommended by SlowMist; coding agents are outpacing human auditors
4. **Supply chain auditing** — Lock dependency versions; verify extension/package provenance; monitor for auto-update supply chain attacks
5. **Safe module review** — Audit all third-party Safe modules for msg.sender vs. caller-data trust assumptions
6. **Real-time monitoring** — Blockaid/Hypernative-style detection; Wasabi funds were consolidating hours before the team's first statement
