## 3. ERC-8183 / ACP Contract Risk Assessment

### What is ERC-8183?
ERC-8183 (Agentic Commerce Protocol) is the on-chain standard for AI agent-to-agent commercial transactions, introduced February 2026 by Virtuals Protocol + Ethereum Foundation dAI team. It defines a **Job primitive** (posted → escrowed → delivered → evaluated → settled) and introduces an **Evaluator** role that can be an AI agent, ZK verifier, or multisig DAO.

### Deployed Contracts (Base Mainnet)
- Evaluator: `0x119299F3…C091` (Base Mainnet)
- Evaluator: `0x04Ae807b…52e7` (Base Sepolia)
- ACP job contracts: Live on Base, integrated with x402 (HTTP 402 payments) and ERC-8004 (agent identity/reputation)
- Sentinel reputation provider writing on-chain attestations to ERC-8004 registries on Ethereum, Base, and Solana

### Specific Vulnerability Vectors for ERC-8183

| Vector | Risk | Detail |
|--------|------|--------|
| **Evaluator manipulation** | 🟡 MEDIUM | Evaluator role controls job settlement. If an attacker compromises or manipulates the evaluator (especially AI-based multi-model consensus), they can force false job completions or rejections. The MDI threshold (default 0.700) is configurable per contract — misconfigured low thresholds are exploitable. |
| **Escrow lockup / griefing** | 🟡 MEDIUM | The 4-state Job lifecycle (Posted → Funded → Delivered → Settled) has deadlock potential if an evaluator becomes unresponsive or a provider abandons mid-job. No on-chain timeout mechanism is mandated by the standard. |
| **Hook injection** | 🟡 MEDIUM | ERC-8183 supports modular Hooks for extensions (reputation gating, bidding). Malicious or poorly audited Hooks could introduce access control bypass or reentrancy in the escrow flow — same pattern as the Arcadia Finance $3.5M Base exploit (malicious swapData via `router.call(data)`). |
| **ERC-8004 identity spoofing** | 🟡 MEDIUM | Agent identity (ERC-8004) gates reputation. If an attacker registers a spoofed identity with high reputation scores (or reuses a compromised agent's identity), they can post/accept jobs fraudulently. |
| **Bridge dependency (x402 on Base)** | 🔴 HIGH | x402 payment flows settle on Base. Any Base-bridge vulnerability (the same class that hit Kelp DAO via LayerZero) could disrupt payment settlement or allow message spoofing between L1→L2. |
| **Wasabi Protocol pattern (admin key → UUPS upgrade)** | 🔴 HIGH | If any ERC-8183 contract uses UUPS upgradeable proxies with admin keys (no multisig, no timelock), the same pattern as the Wasabi Protocol $5.9M exploit applies. All deployers should verify timelock + multisig on upgrade functions. |
| **Supply chain (dependency attacks)** | 🔴 HIGH | The rekt.news "Poisoned Pipeline" incident showed a VS Code extension auto-updated to 2.2M developers, exfiltrating 3,800 GitHub repos. If ERC-8183 implementations import compromised SDKs (e.g., pot-sdk, @prxvt/hook), the entire escrow flow is compromised at the dependency level. |

## 4. Base Chain Specific Threats

1. **Arcadia Finance ($3.5M on Base)**: RebalancerSpot contract at `0xC729213B9b72694F202FeB9cf40FE8ba5F5A4509` had an arbitrary `router.call(data)` vulnerability in `_swapViaRouter()`. Same pattern is applicable to any ERC-8183 Hook that makes external calls.

2. **Bridge message spoofing**: Kelp DAO's $292M exploit used LayerZero message spoofing. If ERC-8183's cross-chain settlement (L1↔Base) uses LayerZero or similar messaging, the same attack vector exists.

3. **Base validator set centralization**: Base's sequencer is operated by Coinbase. While not yet exploited, a compromised sequencer could reorder/censor ERC-8183 job settlement transactions.

4. **No Base-specific major hacks in 2026 (yet)**: Base has been relatively quiet compared to Ethereum L1 and Solana, but the Arcadia Finance exploit demonstrates that Base is not immune.

## 6. Recommendations

1. **Audit all ERC-8183 contracts on Base** — especially the Evaluator, Hooks, and upgrade proxy patterns. Verify multisig + timelock on all admin/upgrade functions.
2. **Implement bridge-agnostic settlement** — avoid single-bridge dependency for L1↔Base job payment flows; add fallback settlement paths.
3. **Hardened agent key management** — enforce multisig on all ACP agent wallets; eliminate single-key admin patterns (the #1 exploit class of 2026).
4. **Supply chain pinning** — pin all SDK/dependency versions; audit @prxvt/hook, pot-sdk, and acp-cli before use; monitor for auto-update attacks.
5. **Evaluator redundancy** — deploy multi-evaluator consensus with diverse model providers to prevent single-point evaluator compromise; enforce minimum MDI thresholds per job value tier.
6. **On-chain timeout mechanisms** — add mandatory settlement deadlines to prevent escrow griefing/deadlock in the Job lifecycle.
7. **Monitor PeckShield / CertiK alerts** — integrate real-time alerts for Base and Ethereum L1 incidents that could cascade to ERC-8183 contracts.
