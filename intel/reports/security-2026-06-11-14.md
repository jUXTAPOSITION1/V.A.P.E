## VAPE Impact Assessment

### ERC-8183 / ACP Contract Exposure

**Status: ELEVATED RISK — NEW STANDARD, IMMATURE AUDIT SURFACE**

ERC-8183 (Agentic Commerce Protocol) was proposed February 25, 2026 by Virtuals Protocol and the Ethereum Foundation's dAI team. Key risk vectors for ACP/ERC-8183 deployments:

1. **Draft Status** — ERC-8183 is still in Draft. No final audit trail. The Ethereum Magicians discussion (March 2026) raised critical design concerns:
   - DanielVF: "Why can the client not release funds themselves?" — speed and privacy implications in non-dispute cases.
   - gpt3_eth: Linked/two-phase job semantics not fully solved — stateful DeFi workflows (yield strategies, open/close positions) may not fit the one-shot lifecycle model.

2. **Evaluator Centralization Risk** — The Evaluator is a single on-chain address. If compromised or malicious, it can reject valid work or complete invalid work. This mirrors the admin key compromises that devastated Wasabi Protocol ($5.9M) and DxSale ($7.3M) in 2026.

3. **Hook Attack Surface** — ERC-8183's extensibility via hooks is both a strength and a vulnerability. Custom hooks for domain-specific economics are unaudited by default. The `@prxvt/hook` privacy layer (AES-256-GCM + ECDH + ZK proof) exists but is community-maintained, not formally audited.

4. **Escrow Lock-Up Risk** — The `claimRefund()` function after expiry creates a griefing vector: a malicious evaluator could delay resolution, locking client funds indefinitely until the timeout triggers.

5. **No On-Chain Dispute Resolution** — Unlike Kleros or Aragon Court, ERC-8183 has no built-in appeals process. Evaluator attestation is final. A corrupted or buggy evaluator decision is irreversible on-chain.

### Base Chain Exposure

**Status: MODERATE — NO DIRECT INCIDENTS, INDIRECT EXPOSURE VIA BRIDGES**

- No direct Base chain exploits identified in the current sweep period.
- **Indirect risk:** Base relies on the Ethereum L1 for settlement and the Superchain bridge infrastructure. The Kelp DAO $292M exploit demonstrated that bridge vulnerabilities at the L1/L2 interface can be catastrophic. Any ACP contracts on Base that interact with cross-chain bridges inherit this risk.
- **Specific concern:** Wasabi Protocol's UUPS upgrade vulnerability affected vaults across 4 chains. If ACP contracts on Base implement upgradeable proxy patterns without multisig + timelock, the same attack vector applies.
