### Positive Security & Design Patterns

1. **Robust PR Injection Mitigation (`agents/code_review.py`)**
   The docstring highlights a highly secure design pattern: the automated reviewer workflow triggers on `pull_request` (not `pull_request_target`) and reads the PR diff/contents entirely via the GitHub REST API (`GitHubMCPWrapper`) rather than checking out or executing the untrusted fork's code. This completely eliminates the "pwn request" class of workflow injection vulnerabilities.

2. **State-Change Memory Logging (`agents/cdp_bazaar_check.py`)**
   The script avoids polluting VAPE's Central Memory with repetitive polling noise by only logging a finding when a real indexing state *change* is detected (e.g., transitioning from unindexed to indexed), rather than logging on every single run.

3. **Sandboxed Code Generation (`agents/build_request.py`)**
   Autonomous code generation triggered by the `vape-build` issue label is safely sandboxed. Generated files land in an isolated `build-requests/issue-<N>-<slug>/` directory via a PR rather than modifying the active codebase directly, enforcing a mandatory human-in-the-loop review gate.
