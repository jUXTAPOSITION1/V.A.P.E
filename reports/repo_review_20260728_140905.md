### 🚨 Bugs & Security Issues

#### 1. Risk of DOM XSS via `innerHTML` with manual escaping
*   **File:** `docs/assets/hire.js`
*   **Context:** The comment for `escapeHtml(s)` notes: 
    > *"exception messages can echo back arbitrary text (e.g. from a fetch error) — both get written into innerHTML below, so escape them at the sink"*
*   **Issue:** Relying on manual regex-based escaping (`escapeHtml`) combined with `innerHTML` is a known anti-pattern. If a developer forgets to wrap a new dynamic variable in `escapeHtml`, or if an exception message contains characters that bypass the basic `/[&<>"']/g` regex in specific contexts (e.g., inside unquoted attributes), the application becomes vulnerable to DOM-based Cross-Site Scripting (XSS).
*   **Remediation:** For dynamic text like exception messages or user-supplied inputs, avoid `innerHTML` entirely. Use `element.textContent` or `element.innerText` which natively treats the input as plain text and prevents script execution.

### 🧹 Dead & Redundant Code

#### 1. Duplicate `escapeHtml` implementations
*   **File:** `docs/assets/hire.js` (and referenced in `docs/assets/report.js`)
*   **Issue:** `escapeHtml` is defined locally in `docs/assets/hire.js`. The comment mentions this is the *"same pattern already used in report.js"*. Reduplicating utility functions across multiple vanilla JS files increases maintenance overhead and the risk of inconsistent security implementations.
*   **Remediation:** Move `escapeHtml` to a shared utility file (or export it from an existing shared module like `docs/assets/icons.js` renamed to `utils.js`) and import it where needed.
